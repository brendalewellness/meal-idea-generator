# Meal Idea Generator · 餐食灵感生成器

一个给营养咨询师在客户会谈现场用的工具：选偏好 → 挑菜 → 一键出「个性化餐食建议」PDF 讲义。
**中英双语一键切换**，32 道菜全部配有真实美食照。

---

## 一句话结论

**完全可行，而且核心难点不在图片。** 她的流程本质是「从固定菜品库里挑菜 + 套一个好看的版式」，这是很成熟的做法。

## 怎么打开

**双击 `index.html`** —— 不需要装任何东西、不需要联网、不需要服务器。

打开后点顶部 **「载入示例」**，会载入示例客户 Sarah（低碳、无乳、无麸质），计划里已排好两天，直接看到完整效果。

`sample/` 里的参考产物：

| 文件 | 内容 |
|---|---|
| `app-screenshot-zh.png` / `app-screenshot-en.png` | 中英文操作界面 |
| `handout-sample-zh.pdf` / `handout-sample-en.pdf` | 导出的讲义成品（各 6 页，两天计划 + 完整食谱） |

## 功能一览

| 能力 | 说明 |
|---|---|
| **中英切换** | 右上角 🌐 按钮一键切换。界面、菜名、**食谱全文**都会跟着换 |
| 偏好筛选 | 碳水档位（不限/低碳/中碳）+ 调理方向（肠道修复/亚洲/快手/免烹/批量预制/高蛋白）+ 饮食类型（素食/纯素/无麸质）+ 忌口（乳/麸质/坚果/蛋/大豆/鱼/贝类/芝麻） |
| 菜品库 | 32 道菜，早餐/午餐/晚餐/加餐 各 8 道，每道含完整食谱 |
| 排计划 | 第 1 天 / 第 2 天，支持拖拽、点选、单个移除 |
| **一键填充** | 按当前筛选条件，自动给某一天配齐早/午/晚 + 2 个加餐 |
| 食谱弹窗 | 点「食谱」查看完整做法，可单独打印一份 |
| **导出 PDF 讲义** | 生成带客户姓名、日期、备注的个性化讲义，可选附上完整食谱 |
| 讲义预览 | 不打印也能先看排版效果 |

语言默认跟随浏览器：中文环境默认中文，其余默认英文。`?lang=zh` / `?lang=en` 可强制指定。

## 怎么分享给她

三种方式，按场景选：

### 方案 A：单文件离线版（最省事，已生成）

```
dist/meal-idea-generator.html     约 3.6 MB
```

**所有图片和菜品库都内嵌在这一个文件里**。直接用微信/邮件发给她，她保存后双击就能用——
不需要文件夹结构、不需要联网、不需要安装任何东西。

⚠️ 注意：`dist/` 里的文件是**构建产物**。改了 `data/meals.js` 或换了图片后，要重新生成：

```bash
python build-standalone.py
```

### 方案 B：发布成在线链接（微信里可直接打开）

把整个项目目录发布成网页，得到一个链接，在微信里点开即可浏览，不需要对方下载任何东西。
适合「给她看一眼效果」或者她自己也会用手机看。

> 这一步会产生一个**公开链接**，需要你确认后再执行。

### 方案 C：真正的 .exe（不推荐）

技术上可以做（Tauri / Electron 把网页打包成桌面程序），但对这个场景是**杀鸡用牛刀**：

- 需要 Node + Rust 工具链，打包出来 50–150 MB
- 每次改菜品都要重新打包
- 她还得过一次安装向导、处理杀毒软件误报

**方案 A 已经达到了 .exe 的全部效果**（双击即用、离线、不依赖环境），而且只有 3.6 MB。
如果确实需要一个「像软件一样」的图标，把 `dist/meal-idea-generator.html` 右键 → 发送到 → 桌面快捷方式即可。

## 怎么加一道菜

打开 `data/meals.js`，照这个格式往数组里加一条（**中英各一套文案**）：

```js
{
  id: 'b9',                       // 唯一，不能重复
  type: 'breakfast',              // breakfast | lunch | dinner | snack
  carb: 'low',                    // low | moderate
  tags: ['asian','quick-easy','gut-healing','vegetarian'],
  contains: ['soy'],              // 含有哪些致敏原
  img: 'miso-soup.jpg',           // 图片文件名，或 null 用占位图
  emoji: '🍜',
  en: {
    name: 'Miso Soup with Tofu', time: '10 min', servings: '2',
    why: '一句话推荐理由，会印在讲义上',
    ingredients: ['Tofu 200g', 'Miso 1 tbsp'],
    steps: ['Boil the water', 'Dissolve the miso', 'Add the tofu'],
    notes: '备注，可选'
  },
  zh: {
    name: '豆腐味噌汤', time: '10 分钟', servings: '2 份',
    why: '一句话推荐理由',
    ingredients: ['豆腐 200g', '味噌 1 汤匙'],
    steps: ['烧水', '化开味噌', '下豆腐'],
    notes: '备注，可选'
  }
}
```

**可用 `tags`**：`gut-healing` `asian` `quick-easy` `no-cook` `batch-cook` `high-protein` `vegetarian` `vegan` `gluten-free`

**可用 `contains`**：`dairy` `gluten` `nuts` `egg` `soy` `fish` `shellfish` `sesame`

配图：把图片丢进 `images/`，在 `img` 里填文件名；填 `null` 就自动用 emoji 占位图。

## 加完菜记得跑校验

```bash
node validate-meals.js
```

会检查：字段是否齐全、中英文案是否配对、id 有没有重复、图片是否存在、
标签是否合法，以及**逻辑冲突**——

- 标了「无麸质」却把 `gluten` 写进 `contains`
- 标了「素食」却含鱼/贝类
- 标了「纯素」却含乳制品/蛋

这类错误直接印到客户手里会很尴尬。目前 **32 道菜全部通过校验**。

## 配图方案（当初的核心问题）

**关键判断：不需要在运行时生成图片。** 她的场景是「固定菜品库 + 挑菜出讲义」，
同一道菜的配图是固定的 —— 所以配图是**一次性准备好、长期复用的资产**。

三条路线：

| 方案 | 成本 | 优点 | 缺点 |
|---|---|---|---|
| **AI 生成**（本项目用的） | 约 5–10 credits/张 | 风格统一、无版权风险、能精确描述菜品 | 一次性成本；与真实出品可能有出入 |
| **图库 API**（Unsplash/Pexels） | 免费 | 真实照片 | 要联网；未必搜得到对得上的图；**商用授权要逐个确认** |
| **占位图**（emoji + 渐变） | 零 | 零依赖、离线可用 | 不真实 |

本项目 **32 道菜全部使用 AI 生成的真实配图**，统一风格（俯拍、自然光、浅色木桌）。

换图：把新图丢进 `images/`，改 `data/meals.js` 里对应的 `img` 字段，然后重新跑
`python build-standalone.py` 更新单文件版。

## 已知限制（有意为之，不是 bug）

- **讲义靠浏览器打印成 PDF**（点「导出 PDF 讲义」→ 打印对话框选「另存为 PDF」）。
  好处是零依赖、所见即所得；代价是没法在代码里直接产出 PDF 文件
- **配图是固定文件，不是实时生成** —— 见上文，这样反而更省钱
- **数据存在浏览器本地**（localStorage），清缓存会丢；换电脑不同步
- **菜品是占位内容**，营养师需要按自己的方案替换。数据结构已经留好了
