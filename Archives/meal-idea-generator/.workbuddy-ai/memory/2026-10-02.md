# 2026-10-02

## 项目：meal_idea_generator（餐食灵感生成器）

朋友（营养咨询师）要的自用工具，用于客户会谈现场：选偏好 → 挑菜 → 出「个性化餐食建议」PDF 讲义。
本次交付：可行性评估 + 完整可运行原型。

### 关键决策
- **技术栈选型：单文件 `index.html` + 独立 `data/meals.js`，双击运行，零依赖。**
  理由：自用工具，不需要构建步骤和后端；`<script src>` 在 `file://` 下可用，避免 fetch 的 CORS 问题。
- **PDF 导出走浏览器打印（`window.print()` + `@media print`），不引入 jsPDF/html2pdf。**
  理由：零依赖、所见即所得；代价是无法在代码里直接产出 PDF 文件。
- **配图采用「AI 生成 + 占位图」混合方案**（用户从三个选项中选的，明确告知过 AI 生图约 5–10 credits/张）。
  8 张 AI 图覆盖四个餐次，其余 24 道用渐变底 + emoji 占位。
  核心判断：她的场景是固定菜品库，配图是**一次性资产**，不需要运行时生成。

### 实现要点
- 菜品库 32 道（早/午/晚/加餐 各 8），含完整食谱、标签、致敏原字段。
- 筛选：碳水档位（单选）+ 调理方向（多选，AND）+ 饮食类型（AND）+ 忌口（命中即排除）。
- 额外功能：「一键填充」（按筛选自动配齐一天）、「载入示例」、`?demo=1` URL 参数。
- 状态存 localStorage。

### 踩坑与经验
- **图片批量生成后要重命名**：ImageGen 输出的文件名是 prompt 前缀 + 时间戳，无法指定文件名。
  技巧：prompt 首词不同 → 文件名前缀不同（如 `of_A_` / `of_T_`），可据此与调用顺序对应。
- **PNG 太大**：AI 图默认 PNG 约 2MB/张。用 Pillow 转 JPEG（quality 85, 缩到 900px）后约 190KB，
  体积降一个数量级。讲义 PDF 从 ~15MB 降到 1.2MB。
- **emoji 占位符在 Windows 下部分渲染成暗色**（🍳/🥣/🥘）。解决：套一个白色圆形底托，
  这样即使 emoji 渲染成暗色也像刻意设计的图标。
- **营养数据的严谨性**：生抽/味噌含麸质，若菜品标了「无麸质」必须改配料为 tamari / 无麸质味噌，
  否则标签与配料自相矛盾 —— 在营养师手里是硬伤。已在 `validate-meals.js` 里加了这类冲突检测。

### 验证手段（可复用）
- `validate-meals.js`：校验菜品字段、id 唯一性、图片路径、标签合法性、逻辑冲突（如标无麸质却含 gluten），
  并对 8 组真实筛选组合做仿真，确保不会选出空结果。
- **Windows 无头截图/打印**（agent-browser 在 Windows 不支持，用系统 Chrome 代替）：
  ```
  chrome --headless=new --virtual-time-budget=4000 --window-size=1520,1500 \
         --screenshot=out.png "file:///.../index.html?demo=1"
  chrome --headless=new --no-pdf-header-footer --virtual-time-budget=4000 \
         --print-to-pdf=out.pdf "file:///.../index.html?demo=1"
  ```
  这是验证打印样式和真实 PDF 产出的有效办法。
- PDF 太大读不了时，用 pymupdf 渲染成 PNG 再查看：
  `page.get_pixmap(dpi=96).save(...)`

### 产物
- `index.html` 应用本体 · `data/meals.js` 菜品库 · `images/` 8 张 AI 图
- `samples/handout-sample.pdf`（6 页讲义成品）· `samples/app-screenshot.png`
- `validate-meals.js` 校验工具 · `README.md`（含可行性评估与图片方案对比）

## 第二轮迭代（同日晚）

用户提了三件事：加中英切换、怎么分享、把占位图全换成真图。

### 1. 中英双语
- **重构 `data/meals.js` 为双语结构**：`{ id, type, carb, tags, contains, img, emoji, en:{...}, zh:{...} }`。
  原先是 `name` + `name_zh` 扁平结构，无法承载双语食谱，所以整体重写。
  每道菜 en/zh 各含 name/time/servings/why/ingredients/steps/notes —— 32 道 × 2 语言全部手写。
- `index.html` 内建 `I18N` 对象（zh/en 各 49 个键），`t()` 取当前语言文案，`c(m)` 取菜品文案，
  `altName(m)` 取另一种语言菜名做副标题。
- 右上角 🌐 按钮，显示**目标语言**（当前中文则显示 EN）。
- 默认语言跟随 `navigator.language`：zh 开头→中文，否则英文。`?lang=zh|en` 可强制。
- **踩坑（重要）**：初始化顺序必须是「先定语言 → 再套示例数据」。
  一开始写成先 `applyDemo()` 后覆盖 lang，导致示例备注用了上一个语言。
  凡是示例/默认文案依赖当前语言的，都要注意这个顺序。

### 2. 全部换成真实配图
- 共生成 **24 张新图**（分 3 批 × 8 张），加上原有 8 张 = **32 张，0 占位图**。
- 统一风格后缀：`natural window light, light rustic wood table, shallow depth of field,
  appetizing, clean minimal composition, magazine quality, no text, no watermark`
- **批量生成后重命名的方法**（关键技巧）：ImageGen 无法指定输出文件名，
  文件名 = prompt 前缀 + 时间戳。让每个 prompt 的**首词不同**，文件名就会是
  `of_o_` / `of_s_` / `of_C_` 等不同前缀，可据此与调用顺序交叉验证。
  每批生成完立刻重命名，避免跨批混淆。
- 仍用 Pillow 转 JPEG（900px / q85），32 张共 5.8MB。

### 3. 分享方案
- **单文件离线版**：`build-standalone.py` 把 `data/meals.js` 内联进 HTML，
  并把所有 `img: 'x.jpg'` 替换为 base64 data URI（压到 640px / q78）→ `dist/meal-idea-generator.html`（3.6MB）。
- 为此在 `index.html` 加了 `imgSrc(m)`：`data:` 开头直接用，否则拼 `images/` 前缀。
  这样同一份代码既支持多文件版也支持单文件版。
- **验证单文件版必须放到隔离目录**（复制到一个没有 `images/`、`data/` 的文件夹再跑），
  否则路径碰巧能解析，测不出真问题。
- .exe 方案（Tauri/Electron）判定为杀鸡用牛刀，已向用户说明理由。

### 校验器升级
`validate-meals.js` 增加：双语字段完整性、中英食材/步骤条数一致性、I18N 双语键集合一致性。
- **又踩一个坑**：我一开始写的规则是「标了 vegan 但 contains 非空 → 报错」，这是**错的**。
  vegan 只排除动物性成分（dairy/egg/fish/shellfish），坚果、大豆、麸质、芝麻都是植物性的。
  校验规则本身写错会造成误报，误报比不校验更糟 —— 会让人开始忽略告警。
